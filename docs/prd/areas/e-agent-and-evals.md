# E - Agent loop and evals

**Goal:** show the kernel working with a real model, and measure what it adds: against no checker, against the `safe-ops-agent-k8s` policy gate, and for human reviewers. Covers goal G6.

Status: **Planned**.

## User stories

- As an **agent developer**, I give my agent the kernel as a tool: it writes a plan, reads Refuted facts and repairs the plan.
- As an **engineering lead**, I see numbers: how often the agent's first plan is Proved, how many bad plans each checker catches, and whether the packet helps people.

## Requirements

### Agent loop

| ID | Requirement | Priority | Status |
| --- | --- | --- | --- |
| E-01 | An agent writes plans in the plan format from a ticket and a snapshot, and submits them to `planproof check`. It holds no cluster credentials (SEC-01). | Must | Planned |
| E-02 | On Refuted or Unknown, the agent gets the facts (not the packet) and may resubmit, up to a fixed number of tries. | Must | Planned |
| E-03 | The loop runs with a scripted model in CI and a real model locally; the real model is reached through an LLM gateway, as in `safe-ops-agent-k8s`. | Should | Planned |

### Seeded tasks and plans

| ID | Requirement | Priority | Status |
| --- | --- | --- | --- |
| E-10 | A task set of at least 10 tasks where finding a plan is harder than checking it: node-pool drains with tight budgets, rollouts with little spare capacity, scale changes near limits. | Must | Planned |
| E-11 | A set of at least 20 seeded bad plans, each labelled with the rule it should break; at least 5 are intent-versus-effect mismatches that every single step would pass. | Must | Planned |
| E-12 | Reported per model: first-try Proved rate, Proved rate after repair, tries used, Unknown rate. | Must | Planned |

### Measurement

| ID | Requirement | Priority | Status |
| --- | --- | --- | --- |
| E-20 | The seeded bad plans, translated to `ChangeRequest`s, run through the `safe-ops-agent-k8s` OPA gate; report what each checker catches. | Must | Planned |
| E-21 | Seeded unsafe plans accepted by the kernel: 0. Any acceptance is a kernel or model bug, recorded as a gap. | Must | Planned |
| E-22 | Reviewer study: a mix of good and seeded bad plans, shown to reviewers either as raw plan YAML or as the packet. Report catch rate, false alarms and time to decide, whatever the result. | Should | Planned |
| E-23 | Results are generated by scripts into `results/`, never typed by hand. | Must | Planned |
